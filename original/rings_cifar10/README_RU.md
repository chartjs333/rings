# Полный CIFAR-10: проверка фазового фильтра

**Дополнение:** выполнен CPU-эксперимент с Random Forest вместо Ridge. Результаты: [FOREST_RESULTS_RU.md](FOREST_RESULTS_RU.md); запуск: [FOREST_README_RU.md](FOREST_README_RU.md). Далее сохранён протокол исходного сравнения Ridge/MLP.

Эксперимент выполнен на 50 000 обучающих и 10 000 тестовых изображений, всех 10 классах CIFAR-10. Фазовая модуляция улучшает линейный контроль, но эта конфигурация уступает MLP по точности. Исходное оптимизированное ядро `rings.hpp` не менялось; добавлен отдельный десятиклассовый readout.

## Результаты

| Модель | Верно / 10 000 | Точность | Обучаемые параметры | Одиночный кадр, мкс | Пакет 128, мкс/кадр |
|---|---:|---:|---:|---:|---:|
| Линейный контроль, gain=0 | 4 110 | 41,10% | 15 370 | 37,98 | 42,32 |
| Фазовый фильтр, gain=0,25 | 4 363 | 43,63% | 15 370 | 44,72 | 50,09 |
| MLP 768→64→10 | 5 196 | 51,96% | 49 866 | 49,14 | 35,41 |

Двусторонний точный тест МакНемара по правильности ответа:

- Фазовый против линейного: 1 057 исправлений и 804 новых ошибки, +2,53 процентного пункта, p=4,90799e-9.
- Фазовый против MLP: 960 исправлений и 1 793 новых ошибки, −8,33 процентного пункта, p=1,72464e-57. Разница в пользу MLP.

В `results/accuracy_with_holm.json` также сохранена поправка Холма на эти два сравнения. Статистический тест характеризует данный набор парных предсказаний, а не доказывает превосходство архитектуры на произвольных задачах.

Для десятиклассового readout нужно 10×(1536+1)=15 370 параметров, поэтому отношение к MLP — 3,24 раза, а не 32. Фиксированные начальные фазы, нормализатор, рабочие буферы и нулевые совместимые placeholder-веса feature-модели в число обучаемых параметров не входят. Число параметров не является измерением всей памяти приложения.

## Протокол

Исходные RGB-изображения 32×32 усредняются блоками 2×2 до 16×16. Средние и масштабы нормализации вычисляются только по соответствующей обучающей части. Внутреннее стратифицированное разделение: 40 000 / 10 000, seed=42. После выбора настроек финальные модели обучены на всех 50 000 изображениях.

Для gain=0 и gain=0,25 независимо проверены Ridge alpha={10,100,1000,10000}; обе модели выбрали 1000. Значение gain=0,25 перенесено из прежней бинарной конфигурации и здесь не подбиралось по тесту. MLP обучается Adam: lr=0,001, weight_decay=0,0001, batch=256, seed=0. По validation среди 10/20/40 эпох выбрано 20. Файл `selected_before_test.json` записан перед оценкой на тесте.

Две тысячи изображений cat/dog из этого теста уже участвовали в предыдущих экспериментах. Поэтому результат нельзя представлять как полностью независимую проверку всей истории разработки. Нового подбора по тестовым ответам в данном запуске не было.

Задержка — медиана 301 измерения после 30 прогревов, один вычислительный поток. Модели измерялись в перемешанном порядке. Время включает pooling, нормализацию, признаки, все 10 оценок и argmax. Исключены загрузка файлов, первоначальное создание входного/выходного буфера и преобразование результатов в Python-списки. Для C++ используется float64, для NumPy/BLAS MLP — float32: это сравнение конкретных реализаций, не одинаковых вычислительных backend. Один кадр повторяется; пакет содержит 128 разных кадров. Исходные измерения и p95 находятся в `results/latency.json`.

Финальное извлечение обучающих признаков и fitting Ridge: фазовый вариант 3,394+3,262 с; линейный 2,690+3,294 с. Финальное обучение MLP — 9,963 с. Эти значения исключают поиск настроек. Все обучение и выбор настроек вместе заняли около 69,2 с в данном окружении.

## Реализация и проверки

`multiclass.hpp` хранит десять векторов коэффициентов и десять смещений. Старый бинарный Classifier возвращает признаки, новый readout вычисляет все оценки и argmax. Это потребовало дополнительной обвязки: простая замена меток не делает старый скалярный C++-выход многоклассовым.

`mc_api.cpp` обрабатывает пакет кадров, проверяет размеры буферов и поддерживает reset/stream. Внутри цикла кадров не выделяет динамическую память. `multiclass.py` предоставляет ctypes-обвязку.

Пройдены 8 C++-тестов и 5 Python-тестов. C++-тесты readout/ядра также пройдены под UBSan; это не утверждение о покрытии санитайзером каждого пути C API. Максимальное расхождение native и scikit-learn оценок на 10 000 тестовых изображениях — 1,45e-15; метки совпали. SHA-256 неизменного `rings.hpp` записан в `results/core_identity.json`.

## Запуск

Требуются Python 3, зависимости из `requirements.txt`, make и C++17-компилятор. Поставленные `.so` собраны для Linux x86-64; на другой системе пересоберите их. Все команды выполняются из каталога проекта.

```bash
python3 -m pip install -r requirements.txt
make -B all
make test
make ubsan
python3 demo.py
python3 benchmark.py
python3 plot_ablation.py
```

Демо и benchmark используют приложенные модели и 128 тестовых кадров из `data/examples.npz`. Для полного переобучения нужен официальный бинарный архив CIFAR-10 с MD5 `c32a1d4ab5d03f1284b67883e8d87530`. Создайте отдельную копию проекта, сохраните прежние результаты, освободите в копии каталог `results`, затем выполните:

```bash
mkdir -p results work
python3 experiment.py --archive /absolute/path/cifar-10-binary.tar.gz
python3 benchmark.py
```

Повторный запуск experiment намеренно запрещен при существующем `results/accuracy.json`. Потребуется свободное место для временных массивов признаков; они не включены в архив. Исходный полный датасет также не включен.
